# GTA IV PS4 build dependency lock

This file records the upstream baseline used by the PS4 port. Do not silently float these
dependencies to newer revisions: the PS4 sysroot, linker, Mesa RADV port and shader tools must
agree with one another.

## Host

- Linux x86_64 (the setup script's DXC asset is Linux x86_64).
- CMake 3.29 or newer, Ninja, Git, curl, tar, Python 3.10+, and LLVM/Clang 21 tools.
- PacBrew OpenOrbis PS4 toolchain, default path `/opt/pacbrew/ps4/openorbis`.
- DolphinPS4's PS4 sysroot: LLVM 21 libc++/libc++abi, `__config_site`, and `libc-overlay`.

## Upstream baselines

| Component | Required baseline |
|---|---|
| DolphinPS4 integration scripts and port | `iHaiDeeZ/DolphinPS4` commit `888ff3e913801c0c2b2531ddf4f767772ed45dd9` |
| Dolphin source used by that integration | `dolphin-emu/dolphin` commit `771fb154059c5812d6a715a23226249cc42877a2` |
| Mesa source | Mesa `26.0.8` |
| PS4-specific Mesa change in this repository | `ps4/patches/mesa-aco-mubuf-addr64.patch` |
| DXC host library | Microsoft DirectXShaderCompiler `v1.9.2609`, asset `linux_dxc_2026_09_28.x86_x64.tar.gz` |
| LLVM host tools | Clang/LLD/LLVM 21 |

The DolphinPS4 build guide is the source for the host prerequisites, Dolphin base revision,
Mesa version and sysroot layout:
https://github.com/iHaiDeeZ/DolphinPS4/blob/888ff3e913801c0c2b2531ddf4f767772ed45dd9/BUILDING.md

The GTA IV port does not build or package Dolphin itself. It consumes the compatible sysroot,
Dolphin's glslang source tree, and a separately configured Mesa static-library build.

## Expected directory layout

Defaults can be overridden with environment variables:

- `DOLPHIN_BUILD`: `$HOME/dolphinps4-build`
- `DOLPHIN_SYSROOT`: `$DOLPHIN_BUILD/sysroot`
- `OPENORBIS`: `/opt/pacbrew/ps4/openorbis`
- `LR_ROOT`: `$HOME/libertyrecomp-ps4-build`

Required inputs include:

- `$DOLPHIN_BUILD/src/dolphin/Externals/glslang/glslang`
- `$DOLPHIN_SYSROOT/include/c++/v1/__config_site`
- `$DOLPHIN_SYSROOT/lib/libc++.a` and `libc++abi.a`
- `$DOLPHIN_SYSROOT/libc-overlay/`
- OpenOrbis `link.x`, `lib/crt1.o`, `lib/libclang_rt.builtins-x86_64.a`, and `bin/create-fself`

The GTA IV-specific build outputs belong under `$LR_ROOT`:

- `oo/` and `llvm/`: generated by `setup-toolchain.sh`
- `host-tools/bin/spirv-val` and `glslangValidator`
- `host-tools/dxc/lib/libdxcompiler.so`
- `mesa-build/`: static RADV libraries consumed by `cmake/PS4Runtime.cmake`

## Validation and build order

Run from the repository root in the Linux build environment:

```bash
python3 tools/setup_repo.py --check
bash ps4/scripts/setup-toolchain.sh
bash ps4/scripts/check-build-prerequisites.sh
bash ps4/scripts/build-ps4.sh all
bash ps4/scripts/package-ps4.sh 01.00
```

The prerequisite checker is read-only and reports every missing file/tool before CMake starts.
It intentionally does not require game data: use only game files you own or are authorized to
use, and keep them out of the repository and CI artifacts. The package contains the runtime and
read-only application resources, not a copy of the game.

## Important distinction

A passing repository-validation workflow checks metadata, shell syntax and path-safety tests. It
does not prove that OpenOrbis, the sysroot, Mesa or the final PS4 executable can be built. A full
native build is only confirmed when the above preflight succeeds and the PS4 configure, compile,
OELF validation and package steps complete on a provisioned Linux x86_64 runner.
